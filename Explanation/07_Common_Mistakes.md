# 07 · Common Mistakes: SquadQuery

**Rule:** for every module, the mistakes that are easy to make here, **how to spot them, how to prevent them and how to debug them**. Mistakes that the checks **actually caught in this project** are marked ⚠ caught; mistakes caught by *other* portfolio projects first and avoided here are marked ⚠ seen elsewhere. This file grows with every step.

---

## Phase 4: project, plugin and configuration

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| ⚠ seen elsewhere: **no `DefaultInput.ini`** in a project with the Enhanced Input plugin enabled (the default) | `LogEnhancedInput: Warning: … does not have a valid PlayerInput object` on every map load | Set `DefaultPlayerInputClass` and `DefaultInputComponentClass` to the Enhanced Input classes, as Epic's templates do (`05` A9) | Grep the game log for `LogEnhancedInput` |
| ⚠ caught: **committing what the editor wrote into config.** The first cook added an Android File Server section with a generated security token to `DefaultEngine.ini` | `git status` shows `DefaultEngine.ini` modified after a build you didn't edit config for | Read every config diff before committing. Remove the cause, not just the text: disable the plugin that writes it (`"AndroidFileServer", "Enabled": false` in the `.uproject`) and delete the section (`05` A1, A7). An intermediate fix (keeping the section with an empty token) was replaced by this one | `git diff SquadQuery/Config`; the writer is `AndroidFileServerRuntimeSettings.cpp:31-36` |
| Passing command-line flags the engine doesn't parse (for example `-ExitAfterSeconds`, which 5.8.4 ignores) | The flag has no effect; the run behaves as if it weren't there | Check that the engine parses a flag (grep for it in `Source/Runtime`) before relying on it | Grep the engine source for the flag name |
| **Forgetting to enable SmartObjects** (it is off by default, `SmartObjects.uplugin:13`) | Link errors or "module not found" once code uses `SmartObjectsModule`; Smart Object components never register | Enable it in the `.uproject` **and** declare it in the `.uplugin` of the plugin that uses it | `-log` start-up lines list the loaded plugins |
| A plugin module depends on another plugin's module without declaring that plugin | UBT warning "Plugin '…' does not list plugin '…' as a dependency" (`UEBuildTarget.cs:1578`) | `"Plugins": [...]` in the `.uplugin` | Read the UBT log; the build must have 0 warnings |
| The game module depends on a plugin module the `.uproject` doesn't list | UBT warning "… does not list plugin '…' as a dependency, but module '…' depends on '…'" (`UEBuildTarget.cs:1687`) | List every such plugin in the `.uproject`, even if it is `EnabledByDefault` | Same |
| **A config section in the wrong `.ini`** (for example the EQS manager, `config=Game`, written into `DefaultEngine.ini`) | The value seems to have no effect; there is no error | Check the class's `UCLASS(config=…)` before choosing the file (`06` §5) | In a running game, the console command `getall EnvQueryManager MaxAllowedTestingTime` prints the live value on every instance (`GETALL`, `Source/Runtime/CoreUObject/Private/UObject/Obj.cpp:4909`) |
| **Leaving the navmesh `Static`** when geometry is spawned at runtime | Agents don't move; `MoveToLocation` fails; the navmesh doesn't cover spawned blocks | `RuntimeGeneration=Dynamic` for `RecastNavMesh` (`05` A7) | `show Navigation` in a game window; `FindPathSync` result in the log |
| Two modules with the same name (for example a plugin named like the game) | UBT silently uses only the first `.Build.cs` it finds (`RulesAssembly.cs:199-206`) | Unique names: `SquadQuery` (game) and `SquadQueryCore` (plugin) | Compare the module list in the UBT log with the folders on disk |
| Making a dependency public "to be safe" | Rebuilds touch more modules than the change warrants | Public only when a public header includes the dependency (`06` §2) | UBT's action count after a header change |
| Writing batch files with LF line endings | Labels and `goto` can misbehave | `.gitattributes` keeps `*.bat` as CRLF; check with `file *.bat` | Run the script from `cmd` with echo on |
| Building or running the game outside the queue | Another project's benchmark is corrupted by the CPU load | Every Unreal job goes through `tools\ue_queue.py` | The queue's `history.jsonl` lists every job |
| Assuming the launcher engine can build every configuration | The Test configuration fails: "Targets cannot be built in the Test configuration with this engine distribution" (UE5-UpdateBudget `09` F-3a) | Headline builds are packaged **Development** | Read the BuildCookRun output |
| ⚠ caught (audit): **checking only the working tree before a push.** The working tree was clean of the Android File Server section, but an intermediate commit had added the key and the next one removed it, so it was still in the unpushed history | `git log -p origin/main..HEAD \| grep <pattern>` finds lines that the current tree no longer has | Audit the **history** that is about to be pushed (`git log -p`), not just `git diff` or the tree; squash before pushing if an intermediate commit carried something that must not be published | `git log -p origin/main..HEAD`, `git log -S <text>` |

## S1: arena, Smart Objects, runtime navigation

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| ⚠ caught (review before the first run): **a check point inside an obstacle.** The first draft put the path-check corners at ±58 m, where a jittered edge block (centres up to ±57 m, half-length 1.5 m) can cover one | A path check that fails on some seeds only | Put probe points where geometry can't be, and derive the margin from the layout constants (`05` B5, `CornerCm`) | Log the start and end projections; draw the navmesh (`show Navigation`) |
| Two random draws in one expression | The arena hash differs between compilers, or between two builds of the same binary type, with the same seed | One draw per statement (`04` §8) | Compare hashes of two runs of the **same** binary. The editor and the packaged game differ anyway, because they use different floating-point modes (`01b` #21, `09` S1 observation 1) |
| Comparing a bit-exact hash across the editor and the packaged build | "Different arenas" for one seed, while every layout statistic matches | Compare like with like: one binary per comparison; measure only in the packaged build (`04` §12) | Log the layout statistics next to the hash; if they match and only the hash differs, it is rounding |
| **Scaling the actor** whose children use centimetre offsets | Smart Object slots appear stretched away from the block | Scale the mesh component, keep the root unscaled (`05` B2) | Compare `GetSlotTransformChecked` with the expected position (the self-check does) |
| A Smart Object slot without a behavior definition | The component never registers; no error, only a `Log`-level line in `LogSmartObject`; queries find nothing | Give every slot (or the definition) a behavior definition (`01b` #19) | `FindSmartObjects` over the whole arena returns 0; raise `LogSmartObject` to `Log` |
| Setting a Smart Object definition after the component registered | A warning "Changing Definition is not supported when the component is registered" | Deferred spawn, set the definition, then `FinishSpawning` (`06` §8) | Grep the log for that warning |
| Holding a runtime-created definition only by raw pointer | Crashes or empty slots after the first garbage collection | `UPROPERTY` on the one owning reference (`06` §7) | Force a collection (`obj gc`) right after the arena is built |
| Trusting "no navigation build in progress" right after spawning the bounds | "Ready" on frame 1 with no navmesh; agents can't move | Wait for the build-finished event, and also require a complete path across the arena (`05` B5) | Log the frame and real time at which readiness is reported |
| ⚠ happened (S1-c): **trusting the build-finished event alone.** The review replaced polling with `OnNavigationGenerationFinishedDelegate` and dropped the path test | `Navigation built 0.376 s` on frame 1, then the self-check: `on navmesh 0; complete corner paths 0/4` | The event fires for **any** finished build, however small (`01b` #20). Keep one path test per event (`05` B5) | The self-check's navmesh counts; `LogNavigationDirtyArea` warnings just before |
| A runtime bounds volume without a body | Bounds are a zero-size box outside the editor; nothing is built | Give the brush component a body setup with a box (`01b` #9) | `getall NavMeshBoundsVolume …` or log `GetComponentsBoundingBox(true)` |
| ⚠ happened (S1-c): **changing what a component's bounds depend on without recomputing them.** The box body was assigned after the volume had registered, so its cached bounds stayed a point | `LogNavigationDirtyArea: Warning: Skipped some dirty area creation due to: 0 invalid bounds, 1 empty bounds (… from: Navigation bounds update)`; no navmesh over the arena | Call `UpdateBounds()` after changing a body setup, mesh extents or anything else `CalcBounds` reads (`05` B5, `01b` #20) | Log `GetComponentsBoundingBox(true)` right before announcing the volume |
| Believing a deferred spawn delays component registration | Code configured "before registration" is in fact configured after it | For an actor with a native root, `SpawnActorDeferred` registers the components at once (`Actor.cpp:4330-4336`); only construction scripts and `BeginPlay` wait for `FinishSpawning` (`06` §8) | Log `IsRegistered()` on the component between the two calls |
| Timeouts in world time in a fixed-step run | The timeout fires too early when frames are fast | Measure real time (`FPlatformTime::Seconds()`) for timeouts | Compare world time and real time in the log |
| Tracing inside the metrics during a measured run | Metrics cost shows up as AI or frame cost, unevenly between configurations | Precompute visibility per threat position before agents exist (`05` B5) | Insights: no `SQArenaVisibility` scene queries inside the capture |
| ⚠ happened (S1-a): **using a type the engine header only forward-declares.** `SmartObjectSubsystem.h` declares `FSmartObjectRequest` and `FSmartObjectRequestFilter` without defining them | `error C2027: use of undefined type` on the line that builds the request | Include the header that *defines* each type you construct (`SmartObjectRequestTypes.h`), not one that merely mentions it (`05` B5) | Search the engine's public headers for `struct FName` (with the opening brace) to find the definition |
| ⚠ happened (S1-b): **relying on a dependency's dependency at link time.** The arena constructs and copies Smart Object types that contain gameplay tag containers, but the module listed only `SmartObjectsModule` | `LNK2019: unresolved external symbol … FGameplayTagContainer::operator=` / `FGameplayTagQuery::FGameplayTagQuery` | List every module whose types your code constructs, copies or calls directly in your own `Build.cs` (`05` B1), even when another dependency lists it publicly **[observed]** | The mangled names in the linker error name the class; find its module with a search for its header under `Engine/Source` and `Engine/Plugins` |

## S2: agents, director, measurement

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| Calling `MoveToLocation` for a goal the agent already has | Move requests per minute far above switches per minute; path queries in Insights every frame | One place turns decisions into movement and returns early for the same slot (`05` C3) | Compare `move_requests` with `switches` in the run report |
| Counting the first decision as a switch | Every configuration shows at least one switch per agent even when nothing changed | A switch needs a previous slot (`05` C3) | A scripted run with a fixed threat: switches must be 0 |
| Measuring time-to-cover from the frame the agent *decides* instead of the frame the event happens | Configurations that decide late look as fast as ones that decide at once | The clock starts at the event (`05` C4) | Plot `seconds_to_cover` against query latency |
| Tracing in the metrics | AI or frame time differs between configurations for reasons that have nothing to do with decisions | Precomputed visibility table (`05` B5) | Insights: no scene queries in `SQBench/Metrics` |
| Starting the capture on the same frame as an event | That event's frame may or may not be in the CSV; event-frame statistics lose one sample at random | Offset captured events by 0.25 s from `BenchStart` (`05` C4) | Count `SQBench/Threat` events in each capture: 10 |
| Summing the percentiles of two columns to get "AI p99" | A p99 that matches no real frame | Sum per frame first, then take percentiles (`csv_stats.py` composite columns) | The self-test checks composite columns |
| Launching the game through `cmd /c start /affinity` | A crashed run reports exit code 0 | Pin the script itself and launch the real executable (`05` C5) | Kill a run on purpose: the script must report it |
| ⚠ caught (review): **reading instance geometry from a class default object.** `GetDefault<ASQAgent>()->GetSimpleCollisionHalfHeight()` | Every agent spawns about 86 cm into the floor and is pushed out by the collision handling; `LogCharacter: WARNING … Called on default object` | Use the API meant for defaults: `GetDefaultHalfHeight()` (`06` §20) | Log the spawn height once |
| ⚠ caught (review): **a timing total that misses a nested engine scope.** The path query inside `MoveToLocation` records into its own exclusive `Pathfinding` stat, which is subtracted from ours | AI time hardly changes when agents switch slots far more often | List every exclusive scope that can run inside yours and add it to the total (`05` C5) | In one capture, compare `Exclusive/GameThread/Pathfinding` with the number of move requests |
| ⚠ caught (review): **a retry that depends on who calls you.** Re-issuing a lost move only when a chooser picks the same slot again | Stranded agents (`-1` time to cover, event after event) in event-driven configurations, never in polled ones | Retry from the engine's own finished-move event (`OnRequestFinished`), identical in every configuration (`05` C3) | `move_retries` and `move_failures` in the agents report |
| ⚠ caught (review): **a template map's player pawn among the agents.** The default game mode spawns an `ADefaultPawn` at the map's `PlayerStart` | Agents near the origin bump into an invisible sphere; the view target jumps when it is possessed | A game mode with no pawn class (`05` C2b) | `LogLoad: Game class is '…'`; list the world's pawns |
| ⚠ happened (S2-a): **agents without avoidance.** Path following avoids blocks but not agents | Some agents never reach cover before the next event (`-1`), each with its capsule against another agent's (centres 68–78 cm apart), and `move_retries` above 0 | `bUseRVOAvoidance` on the character movement (`05` C2) | `final_slot_distance_cm` in the agents report; distance to the nearest other agent |
| A time-to-cover median dominated by agents that never had to move | Median 0.00 s in every configuration | Report the share already in cover and the time over the agents that moved (`05` C5) | Count the zeros in `_events.csv` |
| A run label with a space | The game writes its report under a truncated tag and the script finds nothing | Restrict labels to letters, digits, `_` and `-` (`05` C5) | Compare `-SQRunTag=` in the log with the expected name |
| Counting conflict onsets with state carried over from the warm-up | `conflict_onsets = 0` while `conflict_agent_frames > 0` | Reset the per-slot conflict state at `BenchStart` (`05` C4) | Both numbers are in the report header |

## S3: per-agent baselines

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| ⚠ caught (review): **a poll phase that never takes effect.** A cooldown set before a tick function's first tick is ignored, and a newly enabled tick runs on the next frame | Every polled agent queries on the same first frame; `Queries / s` spikes once per interval instead of spreading | Apply the seeded delay in the first tick (`05` D6, `06` §25) | Count `queries_started` per frame in a capture |
| ⚠ caught (review): **decision work outside the decision stat.** B2's abort on a threat event ran inside the director's timing scope | B2's AI time is lower than its work suggests | Every entry point of decision code opens `SquadQueryDecide` (`05` D6) | Insights: look for EQS calls under `SQBench` |
| ⚠ caught (review): **counting work that didn't happen.** The keep-current item test was counted before the early return that skips the trace | Item tests per second higher than traces in Insights | Count a test next to the call that does it | Compare `keep_checks` with traces |
| ⚠ caught (review): **mixing aborted queries into latency.** An aborted query ends at once | B2's mean query latency far below B0's and B1's for the same query | Count aborted queries apart; latency over completed ones only | `queries_aborted` in the report |
| ⚠ caught (simplify): **a baseline that does avoidable work.** Tracing the current slot even when the new one is more than the keep bonus closer; a new finish delegate per query; resolving the squad on every query | The baseline's AI time includes overhead a careful game wouldn't have, which makes the new method look better than it is | Cheap tests first; bind delegates once; cache what doesn't change (`05` D6) | Insights: our own scopes inside `SquadQueryDecide` |
| Comparing configurations with Development-only engine overhead that scales differently | Per-agent queries pay the EQS debugger's per-query bookkeeping N times as often as squad queries (`01b` #22) | Measure that overhead itself (its cycle stats) and report it next to the result (`02` §12) | `stat AI_EQS` / Insights: `EQS Debug StoreQuery`, `EQS Debug StoreStats` |
| Expecting an agent to see its own claimed slot in its query | With claims, the current slot never comes back, so the agent switches every poll | Check the current slot separately (keep-current rule, `02` §7) | `switches` per agent per event in B1 vs B0 |
| A claim that outlives its holder | Slots stay claimed after agents are destroyed; later queries find fewer slots | Free the claim in `EndPlay` (`05` D6) | Count claimed slots at the end of a run |

## S4: the solver

| Mistake | How to spot it | How to prevent it | How to debug it |
|---|---|---|---|
| ⚠ caught (review): **a non-finite cost in a potential-based algorithm.** One `-inf` turns the potentials into infinities and every reduced cost into NaN; no column wins the search and the loop never ends | The game thread hangs in `Solve` | Treat non-finite costs as forbidden, and ensure on NaN at the entry (`05` E2) | A unit test with `-inf` (`05` E3) |
| ⚠ caught (review): **a size mismatch that looks like a legitimate answer.** A wrong-sized matrix returned "everyone unassigned", the same as "everything forbidden" | A squad that never gets slots, with nothing in the log | `ensureMsgf` on the size, in 64-bit arithmetic | The ensure's callstack names the caller |
| ⚠ caught (review): **a determinism test that can't fail.** Calling a pure function twice in one process and comparing | The test passes after the tie-breaking changes | Pin the exact expected result | Change `<` to `<=` in the search: the pinned test must fail |
| Testing only the assignment, not the returned total | A regression in the final sum passes every test | Compare the returned total with the reference too (`05` E3) | `WrongTotals` in the brute-force test |
| Greedy claiming taken for "good enough" | Totals 2.5× the optimum on simple cases (`04` §15) | Solve exactly; keep greedy only as a measured ablation (`02` §2) | `SquadQuery.Solver.KnownOptimum` |
